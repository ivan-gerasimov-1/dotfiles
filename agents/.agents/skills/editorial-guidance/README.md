# editorial-guidance

Устройство скилла для тех, кто его правит. Модель этот файл не читает, потому что всё
нужное для проверки ей выводят скрипты.

## Файлы

Правила и всё для проверки лежат в каталоге [references/](references/):

- [rules/](references/rules/) содержит по файлу на правило, имя файла совпадает
  с номером правила (`rules/GR003.md`). Frontmatter файла задаёт `id`, `title`,
  категорию (`category`) и языки, для текста на которых у правила есть прочтение
  (`languages`, например `[ru, en]`). Язык указывается без региона, поэтому `en`
  покрывает и en-US, и en-GB. Описание правила написано по-русски и действует
  для любого языка. Примеры и списки для одного языка лежат в его разделе в конце
  файла, `## ru` или `## en`. Раздел необязателен. Скрипт выводит описание
  и раздел языка текста. Поле `checks` называет
  механические проверки правила из `scripts/checks.ts`, например `[connectors]`.
  `glossary: true` ставится правилу, которое читает глоссарий. Агент во флоу
  single и сабагент во флоу parallel получают глоссарий только вместе с такими
  правилами.
- [presets/](references/presets/) отвечает на вопрос «что проверять», по файлу
  на пресет. Frontmatter задаёт `id`, `title` и правила: либо `rules`, список
  отдельных правил, либо `groups`, правила по группам. `extends` добавляет к ним
  правила и группы других пресетов, на один уровень. Список групп скрипт
  выводит сам из frontmatter в разделе «Группы», а текст пресета описывает к ним
  дополнения, оценку и свои разделы отчёта. Пресет описывает только
  свои правила и группы, про другие пресеты он не знает. Всё, что пресет добавляет
  к правке, лежит рядом в `<id>.fix.md` под заголовком «Правка пресета <id>».
  В самом пресете текста о правке нет, это проверяет `rules.ts --check`.
- [categories.md](references/categories.md) перечисляет категории правил, то есть
  виды дефектов. Категория описательная, и скрипты по ней правила не выбирают.
- [flows/](references/flows/) отвечает на вопрос «как проверять», по файлу на флоу.
- [fix/](references/fix/) задаёт, как править. Общие правила лежат в `common.md`,
  и для каждого флоу есть свой файл с порядком правки.
- [report.md](references/report.md) содержит общий шаблон отчёта.
- [scope.md](references/scope.md) говорит, что не проверяется. Его получает тот,
  кто проверяет: агент во флоу single и сабагент во флоу parallel.
- [subagent-prompt.md](references/subagent-prompt.md) содержит задание сабагенту
  группы во флоу parallel.
- [glossary/](references/glossary/) содержит общий глоссарий: что не переводить, чем
  заменять и какие кальки допустимы. Формат глоссария описан в разделе
  [«Формат глоссария»](#формат-глоссария).

## Порядок правил

Сначала проверяются отдельные правила, потом группы. В каждой части свои правила
и группы пресета идут первыми, унаследованные после них, в порядке `extends`.
Селекторы вызова работают как пресет, который расширяет названные пресеты,
а номера правил в них считаются отдельными правилами.

Группа проверяется целиком и один раз, даже если её правило стоит и в другой
группе. Отдельное правило проверяется один раз и выпадает, если его уже содержит
выбранная группа. Поэтому `prose GR003` проверяет то же, что `prose`.

## Скрипты

Агент вызывает только [scripts/prompt.ts](scripts/prompt.ts). Он печатает всё,
что нужно для проверки, одним выводом:

- без флагов (флоу single): описание флоу, шаблон отчёта, правила правки, что
  не проверяется, глоссарий, если правилам он нужен, тексты пресетов и их правки,
  правила и результаты механических проверок;
- с `--copydesk` (флоу parallel): описание флоу, шаблон отчёта, правила правки,
  задание сабагенту, тексты пресетов и их правки, группы;
- с `--dry-run`: то же без правил правки и правок пресетов;
- с `--subagent`: что не проверяется, правила группы, глоссарий, если правилам
  он нужен, и результаты их механических проверок.

Из глоссариев он выводит только записи, термины которых есть в тексте.
Общий глоссарий идёт только к русскому тексту, а проектный к тексту на любом языке.
Проектный глоссарий он ищет по строке `editorial-guidance glossary: <путь>`
в ближайшем `AGENTS.md` или `CLAUDE.md` над документом, для текста из чата над
рабочим каталогом. Язык текста он определяет по буквам прозы, если его не задаёт `--lang`. Текст из чата
приходит на stdin (`-` вместо файла) и сохраняется во временный файл. Вывод одной
проверки обрезается на 40 строках. Весь вывод длиннее 28 тыс. символов уходит
во временный файл, потому что предел вывода команды в Claude Code 30 тыс. символов.

Остальные скрипты служат ему библиотекой:

- [scripts/rules.ts](scripts/rules.ts) читает пресеты и правила и задаёт порядок
  проверки.
- [scripts/checks.ts](scripts/checks.ts) содержит механические проверки.
  `checks.ts <проверка> <файл>` выводит одну проверку целиком. Он нужен, когда
  вывод в `prompt.ts` обрезан, и после правок.

Записки для того, кто правит скилл, лежат в файлах в HTML-комментариях
(`<!-- … -->`). Скрипты их не печатают.

`rules.ts --check` проверяет, что пресеты, правила и проверки сходятся. Запускай его после
правок в пресетах и во frontmatter правил. После правок в самих скриптах запускай
их тесты, `node --test scripts/*.test.ts`.

Скрипты написаны на TypeScript. Им нужен Node 22.18 или новее, такой Node
запускает `.ts` без сборки.

## Примеры вызова

| Вызов | Что происходит |
|---|---|
| `/editorial-guidance` | правка по `recommended` одним агентом |
| `/editorial-guidance --dry-run` | отчёт по `recommended`, текст не меняется |
| `/editorial-guidance slop -n` | отчёт по слопу с оценкой от 1 до 5 |
| `/editorial-guidance article -c` | правка документа по слопу и языку, сабагенты по группам, как на copy desk |
| `/editorial-guidance task` | правка описания задачи: каркас разделов, код, критерии и язык |
| `/editorial-guidance GR003 CA001 --dry-run` | отчёт только по двум правилам |
| `/editorial-guidance light <текст>` | быстрая и простая правка |

`-c` и `-n` — короткие формы `--copydesk` и `--dry-run`.

## Формат глоссария

Общий и проектный глоссарии пишутся в одном формате, потому что скрипты находят
термины записи по нему. Запись, термин которой они не нашли, выпадает из вывода молча.

- Раздел `## Не переводить` и раздел `## Допустимые кальки` состоят из пунктов
  списка, по пункту на запись. Термины стоят в начале пункта до ` — ` и разделяются
  косой чертой или запятой: `- скилл / скиллы — пояснение`. Вместо этого пункт
  может начинаться с метки жирным и списка терминов через запятую до точки:
  `- **Аббревиатуры:** DTO, API.` Термины в скобках в этой части тоже считаются.
  Запятая и косая черта внутри обратных кавычек термин не делят, поэтому
  `` `Record<K, V>` `` остаётся одним термином.
- Запрещённый перевод пишется в «ёлочках», по одному варианту в каждых:
  `Не переводить как «точка входа» или «точка доступа».` По нему запись тоже
  попадает в вывод, когда в тексте стоит неверный перевод.
- Раздел `## Заменять` — таблица из двух колонок. В левой колонке стоят термины
  через запятую или косую черту, и пояснение в скобках скрипт термином не считает.
  В правой колонке стоит замена.
- Подразделы `###` внутри разделов допустимы. Текст вне списков и таблиц выводится
  вместе со своим разделом. Раздел, у которого не осталось ни одной записи, выпадает
  целиком, с заголовком и текстом.

Таблицу «Заменять» читает механическая проверка `glossary`, а термины из списков
пропускает проверка `latin`.

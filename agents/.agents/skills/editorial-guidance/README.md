# editorial-guidance

Устройство скилла для тех, кто его правит. Модель этот файл не читает, всё нужное
для проверки ей выводят скрипты.

## Файлы

Правила и всё для проверки лежат в каталоге [references/](references/):

- [rules/](references/rules/) содержит по файлу на правило, имя файла совпадает
  с номером правила (`rules/GR003.md`). Frontmatter файла задаёт `id`, `title`,
  категорию (`category`) и языки, для текста на которых у правила есть прочтение
  (`languages`, например `[ru, en]`). Язык указывается без региона, поэтому `en`
  покрывает и en-US, и en-GB. Описание правила написано по-русски и действует
  для любого языка. Примеры и списки для одного языка лежат в его разделе в конце
  файла, `## ru` или `## en`. Раздел необязателен, `rules.ts` выводит описание
  и раздел языка текста. Поле `checks` называет
  механические проверки правила из `scripts/checks.ts`, например `[connectors]`.
- [presets/](references/presets/) отвечает на вопрос «что проверять», по файлу
  на пресет. Frontmatter задаёт `id`, `title` и правила: либо `rules`, список
  отдельных правил, либо `groups`, правила по группам. `extends` добавляет к ним
  правила и группы других пресетов, на один уровень. Список групп `rules.ts`
  выводит сам из frontmatter в разделе «Группы», а текст пресета описывает к ним
  дополнения, оценку и свои разделы отчёта. Пресет описывает только
  свои правила и группы, про другие пресеты он не знает.
- [categories.md](references/categories.md) перечисляет категории правил, то есть
  виды дефектов. Категория описательная, скрипты по ней правила не выбирают.
- [flows/](references/flows/) отвечает на вопрос «как проверять», по файлу на флоу.
- [fix.md](references/fix.md) задаёт, как править с `--fix`.
- [report.md](references/report.md) содержит общий шаблон отчёта.
- [subagent-prompt.md](references/subagent-prompt.md) содержит задание сабагенту
  группы во флоу parallel.
- [glossary/](references/glossary/) содержит общий глоссарий: что не переводить, чем
  заменять и какие кальки допустимы.

## Порядок правил

Сначала проверяются отдельные правила, потом группы. В каждой части свои правила
и группы пресета идут первыми, унаследованные после них, в порядке `extends`.
Селекторы вызова работают как пресет, который расширяет названные пресеты,
а номера правил в них считаются отдельными правилами.

Группа проверяется целиком и один раз, даже если её правило стоит и в другой
группе. Отдельное правило проверяется один раз и выпадает, если его уже содержит
выбранная группа. Поэтому `prose GR003` проверяет то же, что `prose`.

## Скрипты

- [scripts/rules.ts](scripts/rules.ts) выводит тексты выбранных пресетов, потом
  правила на языке текста. Про правило, названное по номеру, но не написанное для
  этого языка, он пишет отдельной строкой. Режимы:
  - `--notes` выводит только тексты пресетов;
  - `--groups` выводит отдельные правила и группы в порядке проверки;
  - `--ids` выводит номера правил;
  - `--checks` выводит механические проверки выбранных правил для языка текста.
- [scripts/context.ts](scripts/context.ts) выводит всё остальное для проверки:
  флоу, шаблон отчёта, с `--fix` ещё
  [fix.md](references/fix.md). Для single на русском тексте он добавляет общий
  глоссарий, для parallel задание сабагенту.
- [scripts/checks.ts](scripts/checks.ts) запускает механические проверки.
  `--list <ru|en>` выводит проверки, которые работают для языка.

`rules.ts --check` проверяет, что пресеты, правила и проверки сходятся. Запускай его после
правок в пресетах и во frontmatter правил. После правок в самих скриптах запускай
их тесты, `node --test scripts/*.test.ts`.

Скрипты написаны на TypeScript. Им нужен Node 22.18 или новее, такой Node
запускает `.ts` без сборки.

## Примеры вызова

| Вызов | Что происходит |
|---|---|
| `/editorial-guidance` | отчёт по `recommended` одним агентом |
| `/editorial-guidance --fix` | правка по `recommended` |
| `/editorial-guidance slop` | отчёт по слопу с оценкой от 1 до 5 |
| `/editorial-guidance full --flow parallel --fix` | правка по всем правилам, сабагенты по группам |
| `/editorial-guidance GR003 CA001` | отчёт только по двум правилам |
| `/editorial-guidance light <текст>` | быстрая и простая проверка |

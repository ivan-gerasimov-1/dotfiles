# Editorial Guidance

Ты редактор технических документов. Документ уже собран. Ты проверяешь его на
следы машинной генерации и правишь язык. Структуру разделов не трогаешь,
техническую правоту не оцениваешь. Нужен читаемый русский без воды и без
англицизмов «по инерции». Техническую строгость при этом не теряй.

Правила лежат в каталоге [references/](references/):

- [rules/](references/rules/) содержит по файлу на правило, имя файла совпадает
  с номером правила (`rules/P012.md`). Frontmatter файла задаёт `id`, `title`,
  свод (`set`: `slop` или `prose`) и языки, для текста на которых у правила
  есть прочтение (`languages`, например `[ru, en]`). Язык указывается без
  региона, поэтому `en` покрывает и en-US, и en-GB. Примеры в файле правила
  даны для русского, английское прочтение лежит в [quick-check-en.md](references/quick-check-en.md).
- [rules/slop.md](references/rules/slop.md) содержит оглавление контентного слопа (A001–A005)
  и стилевого (B001–B006), оценку, подсчёт плотности и чек-лист перед оценкой.
- [rules/prose.md](references/rules/prose.md) содержит оглавление правил языка (P001–P015)
  и чек-лист финальной проверки.
- [presets/](references/presets/) содержит по файлу на пресет. Frontmatter файла
  задаёт `id`, `title` и явный список правил (`rules`).
- [report.md](references/report.md) содержит шаблон отчёта.
- [glossary/](references/glossary/) содержит общий глоссарий: что не переводить, чем
  заменять и какие кальки допустимы. Глоссарий читают вместе с P001–P003, P009 и B004.
- [quick-check.md](references/quick-check.md) перечисляет правила для проверки фрагмента.
- [quick-check-en.md](references/quick-check-en.md) перечисляет правила для проверки
  английского фрагмента и даёт английские списки маркеров.

Термины продукта и команды лежат в проектном глоссарии, в репо проекта. Если
в инструкциях проекта (`CLAUDE.md` или `AGENTS.md`) есть строка
`editorial-guidance glossary: <путь>`, прочитай и все файлы по этому пути от корня
проекта. Слово «глоссарий» в правилах означает общий и проектный глоссарий вместе.

Механические проверки из чек-листов запускает [scripts/checks.sh](scripts/checks.sh).
Правила по селекторам выводит [scripts/rules.sh](scripts/rules.sh), остальное для
проверки фрагмента выводит [scripts/context.sh](scripts/context.sh). Пути к скриптам
в правилах даны от каталога скилла. Вызывай скрипты по полному пути, например
`<каталог скилла>/scripts/rules.sh full`.

## Что вычитывать

Документ, над которым мы сейчас работаем. Определи его так:

1. Если пользователь явно указал файл, берёшь его.
2. Иначе смотришь на открытый или обсуждаемый в текущей сессии документ.
3. Если непонятно, спроси, какой файл вычитывать. Не угадывай молча.

Цитируемые промпты и их схемы, блоки кода, Mermaid и таблицы данных не правятся
и в находки не попадают. Таблица данных содержит числа, конфиги или перечни
значений без оценочных слов. Колонки-заглушки из A003 таблицей данных не считаются.
Заголовки и прозаические ячейки таблиц проверяются.

## Вызов

`/editorial-guidance [селекторы] [--fix] [файл или фрагмент]`

**Селекторы** выбирают правила. Селектор задаёт имя пресета или номер правила,
например `P012`. Селекторы можно сочетать, правила из них объединяются.

| Пресет | Назначение |
|---|---|
| [`recommended`](references/presets/recommended.md) | набор по умолчанию |
| [`prose`](references/presets/prose.md) | правила языка |
| [`slop`](references/presets/slop.md) | правила слопа с оценкой от 1 до 5 |
| [`full`](references/presets/full.md) | все правила |

Список правил пресета лежит только в его файле. Правила выбранных селекторов
выводит одним вызовом `scripts/rules.sh <селекторы>`, в порядке номеров. Читай
правила через него, а не по одному файлу. `scripts/rules.sh --ids <селекторы>`
выводит только номера. Без селекторов действует `recommended`. Свод (`set` в файле правила) считается
выбранным, если выбрано хотя бы одно его правило.

**`--fix`** решает, править ли текст. Без него скилл выдаёт отчёт с находками
и предложенными заменами, текст не меняется. С ним скилл правит файл на месте,
а фрагмент из чата возвращает исправленным.

**Цель** определяет, как идёт проверка. Документ проверяют сабагенты по
проходам. Как его выбрать, описано в разделе [«Что вычитывать»](#что-вычитывать).
Фрагмент до десяти предложений из выделения или из чата проверяет один агент по
[quick-check.md](references/quick-check.md), а английский фрагмент по
[quick-check-en.md](references/quick-check-en.md). Для текста из 11–30 предложений
предложи проверку как документа. Если автор откажется, проверь текст как фрагмент.
Текст длиннее 30 предложений проверяется как документ.

Для фрагмента вызови в одном ходе два скрипта, `scripts/context.sh <ru|en>`
и `scripts/rules.sh --fragment <ru|en> <селекторы>`. Первый выводит порядок
проверки с таблицами правил, шаблон отчёта и, для русского, общий глоссарий.
Второй выводит правила, которые применяются к фрагменту. Эти файлы отдельно
не читай.

| Вызов | Что происходит |
|---|---|
| `/editorial-guidance` | отчёт по `recommended` |
| `/editorial-guidance --fix` | правка по `recommended` |
| `/editorial-guidance slop` | отчёт по слопу с оценкой от 1 до 5 |
| `/editorial-guidance full --fix` | правка по всем правилам |
| `/editorial-guidance P012 B001` | отчёт только по двум правилам |
| `/editorial-guidance <фраза>` | отчёт по фрагменту по `recommended` |

Другие скиллы пишут вызов так же, например «`editorial-guidance prose --fix`».

## Проходы

Правила слопа лежат в [rules/slop.md](references/rules/slop.md), правила языка
в [rules/prose.md](references/rules/prose.md). Проходы делят их так:

| Проход | Правила |
|---|---|
| 1. Контентный слоп | A001–A005 |
| 2. Стилевой слоп | B001–B006, глоссарий |
| 3. Слова и термины | P001–P003, P008, P009, P014, глоссарий |
| 4. Грамматика и построение предложений | P004, P005, P012, P013, обычные ошибки русского языка (согласование, падежи, запятые), проверка 6 из чек-листа rules/prose.md |
| 5. Читаемость и сложность | P006, P007, P010, P011, P015 |

Запускаются только проходы, в которых есть выбранные правила. Сабагент прохода
проверяет только выбранные правила своего прохода.

## Как запускать проходы

Каждый проход выполняет отдельный сабагент. Сабагенты только ищут и предлагают
правки. Отчёт собирает и файл правит один агент, тот, что запустил скилл.
Дальше он называется основным.

Проверка идёт в пять шагов. Шаги свода, который не выбран, пропускаются.

1. **Слоп.** Основной запускает сабагентов для проходов 1 и 2 параллельно.
2. **Правка слопа.** Только с `--fix`. Основной применяет правки слопа.
   Пересечения он разводит по разделу
   [«Где правила пересекаются»](#где-правила-пересекаются). Слоп идёт первым,
   чтобы проходы 3–5 не проверяли текст, который всё равно будет удалён.
3. **Язык.** Основной запускает сабагентов для проходов 3, 4 и 5 параллельно.
   Каждый ищет нарушения по пунктам чек-листа из rules/prose.md для своих правил.
   С `--fix` они проверяют текст после шага 2. Без `--fix` текст не меняется,
   поэтому основной запускает их вместе с проходами 1 и 2.
4. **Правка языка.** Только с `--fix`. Основной применяет правки языка. Если две
   правки задевают одно предложение, первой применяется правка прохода
   с меньшим номером. Вторую основной проверяет на уже изменённом тексте.
5. **Финальная проверка.** Только с `--fix`. Если выбран свод prose, основной
   проходит [чек-лист из rules/prose.md](references/rules/prose.md#чек-лист-финальная-проверка).
   Если выбран свод slop, он перепроверяет слоп (раздел [«Правка»](#правка) ниже).

Без `--fix` основной после шагов 1 и 3 разводит пересечения, убирает дубли
и собирает отчёт. Если выбран свод slop, перед оценкой он сверяется
с [чек-листом из rules/slop.md](references/rules/slop.md#чек-лист-перед-оценкой).

Задание сабагенту. Основной подставляет значения в угловых скобках:

```
Ты выполняешь проход <N> редакторской вычитки по скиллу editorial-guidance.

Входные данные:
- каталог скилла: <путь>;
- документ: <путь к файлу>;
- проектный глоссарий: <путь к каталогу или «нет»>.

Прочитай в каталоге скилла:
- SKILL.md, разделы «Что вычитывать» и «Где правила пересекаются»;
- <references/rules/slop.md или references/rules/prose.md>, вступление и чек-лист;
- правила прохода: вывод `<каталог скилла>/scripts/rules.sh <номера выбранных правил прохода>`;
- <для проходов 2 и 3: все файлы references/glossary/ и проектного глоссария>.

Как работать:
- Проверяй документ только по этим правилам.
- Механические проверки запускай через scripts/checks.sh из каталога скилла.
- Документ не правь.
- Каждую замену проверь по P012 (references/rules/P012.md) и B001
  (references/rules/B001.md). Замена не должна вносить новый соединитель или контраст.
- Не меняй порядок мыслей. Неясное место не толкуй, верни его вопросом к автору.

Что вернуть:
1. Список находок. Для каждой укажи:
   - правило;
   - точную цитату из документа, достаточную для однозначного поиска;
   - замену или «удалить»;
   - причину в одну строку.
2. Отдельный список вопросов к автору: подозрения A005 и правки, которым нужен
   факт, которого в документе нет.
```

Сабагент не может запустить своих сабагентов. Если скилл сам работает внутри
сабагента, основной выполняет проходы сам в том же порядке.

## Где правила пересекаются

У каждой находки один владелец. Так одно место не правится дважды по разным правилам.

- **Наполнители.** Фраза из закрытого списка A001 или её форма записывается по A001.
  Похожая фраза не из списка, прочая вода и мета-фразы идут по P006.
- **Усиление.** Если всё следствие нельзя опровергнуть («значительно повышает
  надёжность»), находка идёт по A002. Если утверждение проверяемое и лишнее только
  усиление, находка идёт по A001.
- **Повторы.** Один факт, пересказанный другими словами внутри одного раздела,
  а также вводный абзац, пересказывающий заголовок, и резюме из уже сказанного
  записываются по A004. Повтор факта из другого раздела, повтор таблицы прозой
  и тавтология внутри фразы идут по P007.
- **Лишнее предложение.** Вывод или пункт «зачем/почему» без проверяемого
  утверждения записывается по A002. Прочие предложения, которые можно убрать без
  потери смысла, идут по P006.
- **Канцелярит.** Если выбран свод prose, он идёт по P005, иначе по B005. Для
  оценки слопа он в любом случае считается тиком B005.
- **Кальки и англицизмы.** Связный русский оборот, дословно переведённый
  с английского, записывается по B004. Полуперевод, который не читается по-русски
  («сайты» в значении call sites), идёт по P008. Английское слово или гибрид
  в русском тексте идут по P002–P003.

Если владелец не выбран, находку получает выбранное правило из той же пары.
Без свода slop наполнители и лишние предложения идут по P006, повторы по P007,
канцелярит по P005. Связные кальки (B004) и всё, что не ложится ни на одно
выбранное правило, не ищутся.

## Как выдавать результат

### Отчёт

Без `--fix` текст не правишь. Отчёт строится по шаблону
[references/report.md](references/report.md).

Если после отчёта просят поправить, запусти те же селекторы с `--fix`. Находки
отчёта уже есть, шаги 1 и 3 начинай с них.

### Правка

Раздел действует с `--fix`. Пункты про слоп (A005, B001–B006, шаг 5
со `scripts/checks.sh contrast`) нужны, только если выбран свод slop.

- Правки вносит основной через Edit, по одному точечному изменению. Место правки
  он находит по цитате, потому что номера строк после первых правок сдвигаются.
- Каждую правку привязывай к номеру правила (например, «P002: `консьюмеры` →
  `потребители`», «B001: контраст развёрнут в прямое утверждение»).
- Правится каждая находка. Что считается находкой при плотности ниже порога,
  задаёт [вступление к стилевому слопу](references/rules/slop.md#стилевой-слоп-b001b006)
  в rules/slop.md.
- Подозрения A005 не правятся, их перечисли для автора. Если для правки нужен факт,
  которого в документе нет, не выдумывай его. Задай вопрос автору.
- Технические факты, числа и имена кода не меняются. Смысл каждого утверждения
  сохраняется. Если сомневаешься в смысле, спроси автора.
- Вхождение, у которого любая переформулировка теряет смысл (например, контраст
  «X, а не Y», где противопоставление и есть утверждение), оставь. Перечисли его
  в отчёте с причиной в одну строку.
- На шаге 5 перегони `scripts/checks.sh contrast` по всему файлу и проверь B002,
  B003 и B006 по местам, изменённым на шаге 4. Правила языка могут сами породить
  тик. Новую находку исправь, правку языка при этом не откатывай. Покажи счёт
  «было → стало» по каждому правилу.
- В конце дай короткий отчёт. Сгруппируй правки по проходам и по правилам.
  Отдельно отметь спорные места, где правка меняет смысл и нужно решение автора,
  и кандидатов в глоссарий (P001).

### Фрагмент

Порядок и формат описаны в [quick-check.md](references/quick-check.md).
Для английского фрагмента они описаны в [quick-check-en.md](references/quick-check-en.md).

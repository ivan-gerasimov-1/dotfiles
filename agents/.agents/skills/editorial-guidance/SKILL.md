# Editorial Guidance

Ты редактор технических документов. Документ уже собран. Ты проверяешь его на
следы машинной генерации и правишь язык. Структуру разделов не трогаешь,
техническую правоту не оцениваешь. Нужен читаемый русский без воды и без
англицизмов «по инерции». Техническую строгость при этом не теряй.

Термины продукта и команды лежат в проектном глоссарии, в репо проекта. Его
задаёт строка `editorial-guidance glossary: <путь>` в `AGENTS.md` или `CLAUDE.md`
проекта, путь считается от этого файла. Скрипт сам находит проектный глоссарий
и печатает его вместе с общим. Слово «глоссарий» в правилах означает общий
и проектный глоссарий вместе.

Скрипты лежат в каталоге `scripts/` скилла. Вызывай их по полному пути,
например `<каталог скилла>/scripts/prompt.ts full doc.md`.

## Что вычитывать

Текст или документ, над которым мы сейчас работаем. Определи его так:

1. Если текст передан в вызове или выделен в редакторе, берёшь его.
2. Если пользователь явно указал файл, берёшь его.
3. Иначе смотришь на открытый или обсуждаемый в текущей сессии документ.
4. Если непонятно, спроси, какой файл вычитывать. Не угадывай молча.

Цитируемые промпты и их схемы, блоки кода, Mermaid и таблицы данных не правятся
и в находки не попадают. Таблица данных содержит числа, конфиги или перечни
значений без оценочных слов. Колонки-заглушки из SU002 таблицей данных не считаются.
Заголовки и прозаические ячейки таблиц проверяются.

## Вызов

`/editorial-guidance [селекторы] [--flow single|parallel] [--fix] [файл или текст]`

**Селекторы** выбирают правила. Селектор задаёт имя пресета или номер правила,
например `GR003`. Селекторы можно сочетать, правила из них объединяются. Без
селекторов действует `recommended`.

| Пресет | Назначение |
|---|---|
| [`recommended`](references/presets/recommended.md) | набор по умолчанию для читаемости, для фрагмента и для большого текста |
| [`light`](references/presets/light.md) | быстрая и простая проверка по скриптам и узнаваемым оборотам |
| [`prose`](references/presets/prose.md) | правила языка |
| [`slop`](references/presets/slop.md) | правила слопа с оценкой от 1 до 5 |
| [`full`](references/presets/full.md) | все правила |

**`--flow`** решает, как идёт проверка. По умолчанию действует `single`.

| Флоу | Как идёт проверка |
|---|---|
| [`single`](references/flows/single.md) | всю проверку ведёт один агент |
| [`parallel`](references/flows/parallel.md) | каждую группу проверяет свой сабагент. Это дороже, но длинный документ проверяется тщательнее |

Если во флоу single текст длиннее 30 предложений, в начале ответа предупреди
об этом и предложи повторить проверку с `--flow parallel`. Проверку доведи до конца.

**`--fix`** решает, править ли текст. Без него скилл выдаёт отчёт с находками
и предложенными заменами, текст не меняется. С ним скилл правит файл на месте,
а текст из чата возвращает исправленным. Если после отчёта просят поправить,
запусти те же селекторы с `--fix`. Находки отчёта уже есть, начинай с них.

Другие скиллы пишут вызов так же, например «`editorial-guidance prose --fix`».

## Как выполнять

1. Определи текст по разделу [«Что вычитывать»](#что-вычитывать).
2. Вызови `scripts/prompt.ts <селекторы> [--flow parallel] [--fix] <файл>`.
   Текст из чата передай вместо файла через stdin:

   ```bash
   <каталог скилла>/scripts/prompt.ts <селекторы> - <<'EOF'
   <текст>
   EOF
   ```

   Скрипт печатает флоу, шаблон отчёта, правила и результаты механических
   проверок. Файлы скилла отдельно не открывай. Язык текста скрипт определяет сам
   и называет в первой строке. Если он ошибся, повтори вызов с `--lang ru` или
   `--lang en`. Если вывод сохранён в файл, прочитай этот файл целиком.
3. Действуй по выведенному флоу.

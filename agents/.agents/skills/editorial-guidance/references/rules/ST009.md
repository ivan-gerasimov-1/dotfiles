# ST009. Шаги реализации в описании задачи — свернуть в результат

Пошаговый план реализации в описании задачи читается как предписание, хотя
разработчик может сделать иначе. Описание говорит, что должно получиться, а не
в каком порядке писать код.

Находкой считается список из трёх и более шагов, где каждый шаг описывает
действие в коде: открыть, взять, вызвать, отформатировать, вывести. Такой список
не перечисляет однородные пункты набора, а расписывает одну процедуру. Находка
одна на список.

Не находки:

- сценарий, который проходит пользователь или проверяющий: шаги воспроизведения
  ошибки, ручная проверка;
- порядок, который сам является требованием: сначала миграция, потом выкатка;
- перечень независимых изменений, каждое из которых проверяется отдельно.

При правке список заменяют одним или двумя предложениями о результате. Условия
из шагов сохраняются. Имена кода из шагов не теряются, они уходят в указатели
на код. Шаг, который повторяет условие соседнего шага, удаляют.

## ru

Было:

1. Открыть экран подтверждения.
2. Взять дату окончания из ответа сервера.
3. Отформатировать дату с локалью донора.
4. Вывести дату под суммой, если она есть.
5. Если даты нет, ничего не выводить.

Стало: «Экран подтверждения показывает дату окончания под суммой в формате локали
донора. Если даты окончания нет, строка не выводится.»

## en

Before:

1. Open the confirmation screen.
2. Take the end date from the server response.
3. Format the date with the donor's locale.
4. Show the date under the amount if it is set.
5. If there is no date, show nothing.

After: "The confirmation screen shows the end date under the amount in the donor's
locale. Without an end date, the line is hidden."

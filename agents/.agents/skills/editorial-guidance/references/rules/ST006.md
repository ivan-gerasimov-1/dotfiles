# ST006. Код в описании задачи — роль в прозе, имена в указателях

Имя из кода в прозе описания задачи читается как предписание реализации, хотя
реализация может отличаться. Поэтому в прозе имя кода заменяют ролью: что эта
часть делает для задачи.

Находкой считается имя класса, метода, поля, типа или значения перечисления
в прозе описания. Не находки:

- названия модулей продукта, фич и технологий, термины предметной области
  и термины из глоссария;
- путь публичного API, если он и есть предмет задачи;
- имя внутри блока кода.

При правке имя не теряется. Оно переезжает в раздел указателей на код в конце
описания. Раздел оформлен блоком кода. Первая строка блока содержит комментарий
«отправные точки, реализация может отличаться», дальше по строке на указатель
в формате «Имя — роль». Если имени в блоке ещё нет, его добавляют.

Сниппет или контракт остаётся в описании, только если без него теряется смысл.
Он стоит в блоке кода, первая строка которого содержит комментарий «пример,
реализация может отличаться». Сниппет в прозе и блок без такой пометки считаются
находками.

## ru

Раздел указателей называется «Где смотреть (ориентиры)».

Было: «`WidgetSessionService` пишет `null` в `amountHint`.»
Стало: «Сервис сборки сессии оплаты не заполняет размер одного платежа.»
В «Где смотреть»:

```
// отправные точки, реализация может отличаться
WidgetSessionService — сборка сессии оплаты (сейчас пишет null)
amountHint           — размер одного платежа
```

## en

The pointer section is called "Where to look".

Before: "`WidgetSessionService` writes `null` to `amountHint`."
After: "The payment session service leaves the single payment amount empty."
In "Where to look":

```
// starting points, the implementation may differ
WidgetSessionService — builds the payment session (writes null today)
amountHint           — single payment amount
```

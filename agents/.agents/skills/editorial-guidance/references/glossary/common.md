# Общий глоссарий

Общие термины разработки для правил P1–P3 и P9 из [prose-rules.md](../prose-rules.md)
и допустимые кальки для B4 из [slop-rules.md](../slop-rules.md). Применяется к любому
документу. Термины продукта и команды лежат в проектном глоссарии, его подключение
описано в [SKILL.md](../../SKILL.md). Правила описывают принцип, здесь лежат конкретные списки.

Новый устоявшийся термин добавляет автор, когда принимает кандидата из отчёта
вычитки (P1). Термин одного проекта идёт в проектный глоссарий,
общий термин идёт сюда. Во время вычитки глоссарий не правится.

## Не переводить

### Термины разработки

Не переводятся по P1.

- задеплоен / задеплоить / деплой — устоявшийся технический термин разработки.
- Lazy-чанки / lazy-чанк — устоявшийся термин сборки (разделение кода в rsbuild / webpack).
- пайплайн — допустимый технический термин.
- маппинг / маппит / маппится — устоявшийся термин для преобразования полей между схемами (MongoDB → ClickHouse, DTO → ответ API).
- flow / флоу — устоявшийся термин для пользовательского сценария или потока экранов (checkout flow, onboarding flow). Не переводить как «поток». В формате кода и в составе имени фичи (checkout flow) оставлять английским. В прозе допустимо «флоу».
- downstream / upstream — устоявшиеся термины для положения в потоке данных или зависимостей. Не переводить как «вниз/вверх по потоку» и не разворачивать в «зависимые модули». Оставлять английскими (downstream-модули, upstream-сервис).
- эндпоинт в прозе пишется кириллицей (эндпоинт, эндпоинта). Не заменять на «endpoint» и не переводить как «точка входа/доступа». В формате кода остаётся путь или имя маршрута.
- feature-флаг — устоявшийся термин для флага включения фичи. Не разворачивать в «флаг включения для организации».
- e2e-тесты — тесты сценария целиком (end-to-end). Не переводить как «сквозные тесты».
- билд-агент — машина, на которой Jenkins запускает пайплайны. Не переводить как «агент сборки».
- Jenkins-файл — файл с описанием пайплайна в Jenkins (`Jenkinsfile`). В прозе пишется «Jenkins-файл».
- namespace — пространство имён в Kubernetes. Пишется латиницей и не транслитерируется («неймспейс»).
- stacked PR — цепочка PR, где каждый следующий строится на предыдущем.
- скилл — пакет инструкций для агента (каталог с `SKILL.md`). Не переводить как «навык».
- сабагент — агент, которого другой агент запускает для части работы. Не переводить как «подагент».
- промпт — текст задания для модели. Не переводить как «запрос» или «подсказка».
- слоп — текст со следами машинной генерации. Производные тоже не переводятся (слоп-маркер, слоп-отчёт, антислоп-сигнал).
- заголовок в подбор — короткий заголовок, набранный жирным в одну строку с текстом пункта списка или абзаца. Типографский термин, его не заменяют описанием.
- чек-лист — список проверок, которые проходят по порядку.

### Термины

- **Аббревиатуры разработки:** DTO, REST, API, UI, enum, MVP, PII, CRM, ML, SDK, CDN, PR, PoC, CI, LLM, RFC.
- **Роли:** SDET.
- **Общетехнические (устоявшиеся):** snapshot, interceptor, frontmatter. Не переводятся. «Слепок» допустим только как пояснение к snapshot в определении (не «снимок»).

## Допустимые кальки

Устоявшиеся кальки, которые B4 не помечает.

- «источник истины» (source of truth).
- «исчерпывающий switch» (exhaustive switch).
